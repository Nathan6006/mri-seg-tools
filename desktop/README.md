# The desktop app

An Electron shell around the review tool in [`../web`](../web). The tool
itself — viewer, editor, model, storage — is the same code the browser runs;
see `../web/README.md` for all of that. This folder adds only what a browser
tab cannot do:

- **A double-clickable app.** No dev server, no browser, no URL.
- **Native folder ingest.** *Choose scan folders…* opens a real dialog that
  can select **several folders at once** (the browser file dialog is limited
  to one at a time, by design of the web platform). Bytes are read straight
  from disk as the pipeline asks for them; nothing is copied first.
- **A shared ITK-SNAP folder without the permission dance.** The linked
  folder is a plain path the app remembers. Cases are written there, ITK-SNAP
  saves over the same mask file, and *Check folder for edits* picks the
  changes up — same rule as the browser build, minus the per-session
  re-granting.
- **One-click "Open in ITK-SNAP".** The shell launches `ITK-SNAP -w
  <workspace>` on a case in the linked folder (never `open -a`, which starts
  the app but silently drops the document). Binary found via `$ITKSNAP`, then
  `PATH`, then `/Applications/ITK-SNAP.app`.
- **Durable storage.** Results live in the app's own Chromium profile, so the
  eviction rules that apply to a shared browser (notably Safari's seven-day
  cap) do not apply here. "Download all" is still the only real backup.
- **Bundled model weights.** The packaged app carries `web/model/` inside it;
  the About box states the bundled model versions, since two runs with
  different weights give different volumes.

## How it hangs together

`main.js` serves `../web` over a privileged `app://` scheme with **the same
headers `web/_headers` and `web/serve.py` send** — COOP/COEP for
cross-origin isolation (multi-threaded inference), the CSP, and
`application/wasm`. If you change the headers in one place, change all three.
`file://` would not work: no secure context, no ES modules, no isolation —
and the failure mode is a silent single-threaded slowdown, not an error.

`preload.js` exposes `window.desktopBridge`, a small IPC surface the page
feature-detects exactly the way it feature-detects `showDirectoryPicker`.
The web code branches on it in three places only: `lib/fsaccess.js` (the
shared folder), the scan-folder picker in `app.js`, and the ITK-SNAP
launch/probe in `app.js`. `lib/desktop.js` shapes picked folders into the
same `{path, file}` entries the browser picker produces, so the pipeline
downstream is identical.

Every path that crosses the bridge is validated in the main process: scan
reads only under a folder the user picked in a dialog, case writes only
inside the linked folder, and only a `.itksnap` found inside that folder can
be opened. The renderer names things; the main process decides paths.

## Develop

```sh
cd desktop
npm install
npm start
```

If Electron crashes at startup with `Cannot read properties of undefined
(reading 'isPackaged')`, something in your environment set
`ELECTRON_RUN_AS_NODE` (IDE terminals do this) — the npm scripts already
unset it.

## Test

```sh
npm run smoke        # serving contract: isolation, crypto, model loads
npm run selftest     # the web build's own 43-check suite, inside the shell
```

There is also an end-to-end mode that answers the two native dialogs from the
command line and drives the real page through import → segment → export →
edit-detection → launch validation:

```sh
env -u ELECTRON_RUN_AS_NODE npx electron . \
  --e2e <scan-folder> <export-folder> --profile <scratch-profile-dir>
# then, same profile, to prove results survive a relaunch:
env -u ELECTRON_RUN_AS_NODE npx electron . --e2e-verify --profile <same-dir>
```

Add `--e2e-launch` to also really launch ITK-SNAP on the exported case.
`--profile` keeps test data out of the real user profile. All three modes
exit nonzero on failure.

After changing anything in `../web`, run the plain-browser suites too — the
same files still deploy to the web:

```sh
python3 ../web/test/run_selftest.py
node ../web/test/parity.mjs --sweep 20
```

## Package

```sh
npm run dist         # -> dist/<product>-<version>-arm64.dmg
```

The dmg is unsigned. First launch on another Mac therefore needs
**right-click → Open** once (or System Settings → Privacy & Security →
"Open Anyway"); after that it opens normally. Signing/notarization is a
deliberate later step.

The build packs `../web` into the app's resources **including `web/model/`
if present** — check it is (89 MB + 67 MB), or the app falls back to the
stub with a banner, exactly like a deployment missing its model. The icon is
`build/icon.icns`, generated by `build/make_icon.py`.

## Where things live on a user's machine

| What | Where |
|---|---|
| Results, review status, cached model | the app's Chromium profile under `~/Library/Application Support/MRI Review/` (IndexedDB) |
| The linked ITK-SNAP folder path | `settings.json` in the same directory |
| To reset the app completely | quit it and delete that directory |
